# NS 演示数据

`scripts/generate-ns-data.mjs` 使用 Node.js 22.13 及以上的 `node:sqlite` 生成合成 SQLite 数据。生成过程读取本仓的类型化生成合同，不调用 Telora，不需要旧 NS 源项目检出、Python 或额外 npm 包。

## 生成与使用

在仓库根目录运行：

```sh
node scripts/generate-ns-data.mjs \
  --output bin/ns-data \
  --seed 20261027 \
  --anchor-utc 2026-10-27T00:00:00Z
```

输出目录必须不存在，包含以下文件：

- `ns.sqlite`：151 张物理表、2,118 列、声明粒度唯一索引和关系连接索引
- `model.json`：本次生成使用的字段、最终逻辑类型、业务值域、直接关系及模型源码哈希
- `manifest.json`：生成选项、规则版本与哈希、模型和数据库哈希、行数、时间窗口、身份引用计划、值域覆盖与校验结果

默认种子为 20261027，每表 12 个资源／身份样本，KPI 窗口为 7 天，每小时一个样本；窗口终点默认为当前 UTC 分钟，且不包含该终点。固定种子与 `--anchor-utc` 能复现字节一致的数据库和清单。

`--resources N` 设置每表的基础样本数，范围为 12–10000；`--days N` 设置窗口天数；`--interval-minutes N` 设置采样间隔。KPI 总行数上限为一百万，超限请求在创建输出前拒绝。

默认配置生成 98,004 行，其中 48 张 KPI 表各有 12 条完整序列、每条 168 个样本。默认资源数不覆盖取值超过 12 的值域的全部成员；清单中的 `checks.domains` 分别记录已出现和未出现的规范成员。可用 `--resources 48` 扩大值域覆盖。

## 模型合同

`ns_model/tools/generate_model.py` 在生成 Telora 声明时，同时输出 `data/generation-contract.json`。此合同直接使用同一次生成得到的最终字段类型、空值约束及实际发布的度量名称，Sum 等未发布能力不进入合同。

生成器核对源声明清单和全部模型源码的哈希；模型修改后先运行：

```sh
python3 ns_model/tools/generate_model.py
```

这一步需要 Python。数据生成本身只读取已提交的合同，不重新解释旧时间注解，也不在初始化阶段执行知识发现或完整模型自检。

## 合成场景

资源覆盖网络、PON、FC、服务器、云存储、企业存储及其组件。独立资源身份使用独立命名空间；引用字段逐行选择一个候选资源，避免同一个告警 ID 同时命中所有资源类别。桥接表保留资源标识与数值 KPI 标识之间的连接。

身份引用计划是本工具针对当前 NS 字段设计的夹具规则，记录在 `identityPlan` 中。它通过字段所有权优先级及显式关系选取值来源，不是 ontology 的关系推断能力。生成后逐条检查实际连接覆盖，未覆盖的关系阻止发布。

子网以无自引用的父子链呈现；PON 构造父子分组。资源、组件、桥接表及 KPI 有正向和反向直接关系的实际连接样本；复合键和三个源侧条件关系都有匹配行。多态引用允许一行只匹配一种候选资源，不要求每行命中所有可选关系。

KPI 包含高／中／低负载、日内变化、上升／下降／平稳趋势。明确标注 `%` 的指标限制在 0–100；计数、容量和功率使用合成正数档位。这些是查询演示数值，不承诺设备物理行为或不同指标间的生产级一致性。

告警覆盖严重度、确认／清除状态和多类资源；发生时间在窗口内，清除时间不早于发生时间且早于锚点，未清除使用零。告警名称使用中文场景文本。

`DateTimeUtc` 使用规范 UTC 文本，`EpochMillis` 使用整数毫秒；无时区类型保持无时区表示。未确认单位的原始整数时间字段也填入合成毫秒值，此为夹具假定，不把它们提升为已确认的时间类型。

## 基数与迁移边界

48 张 KPI 表生成多时点序列。现有模型有 16 条直接关系把桥接身份与 KPI 的连接声明为单值，实际观察到的样本行数会超过该上界。清单 `checks.cardinalityExceptions` 明确记录声明基数、两个方向的观察上界及是否由采样行解释。

生成器只容许由 Metric 端多时点采样解释的上界例外；其他基数冲突阻止发布。此工具不修改关系合同，也不宣称这些例外已经修复。它们与完整模型自检的 fuel、92 条未发布 Via 快捷路径及源关系待确认项分别跟踪。

## 校验与发布

生成在目标目录同级的临时目录中进行。SQLite 完整性、字段结构与存储类型、非空约束、唯一粒度、规范值域、时间编码与窗口、序列长度、百分比、告警时间和全部直接关系通过检查后，使用目录重命名发布。已有输出拒绝覆盖，失败清理本次临时输出。

运行生成器回归：

```sh
node scripts/tests/ns-data.test.mjs
```

使用真实 NS 模型 lowering 后的 SQL 验收数据：

```sh
bin/telora -C ns_model build ns_model --staged -o "$TMPDIR/ns.wasm"
node scripts/check-ns-data.mjs bin/ns-data "$TMPDIR/ns.wasm"
```

配额来自 `telora-config.json` 和构建制品，无需在 CLI 重复设置。第三个位置参数可指定独立 `telora-run` 路径。

检查涵盖 151 个 Dataset 投影、302 条关系查询、140 个业务值域筛选、48 个 KPI 聚合与非法输入拒绝。各聚合结果与直接 SQLite 计算逐项对照；只执行 transform 和只读 SQL，不调用运行期知识发现。
