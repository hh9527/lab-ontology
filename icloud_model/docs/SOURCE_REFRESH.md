# Source metadata refresh

Tracked in lab-ontology issue #32, branch `refresh/32-icloud-source-metadata`.
This is an ongoing full-model review, not a declaration that the current
challenge model already covers every source dataset or relation.

## Authority and provenance

The primary inputs are `imaster-cloud/.compact/metadata/*.logical.yaml`
and `*.relation.yaml`. Current business definitions under
`imaster-cloud/telora/src/modeling/icloud` provide secondary interpretations.
Generated data and query examples do not establish physical or business facts.

`../data/source_catalog.json` records all 48 logical datasets, all 97 source
relations, field types, nullability, primary-key markers, descriptions and
semantic properties. Each input file has a SHA-256 digest. The catalog is
review evidence, not a runtime data source or a substitute for model declarations.
It is generated by `scripts/icloud-source-catalog.py` using a YAML parser.

## Confirmed corrections

- `EnterprisePhysicalLink.linkStatus` is the physical status column.
  `link_status` remains the model field name, not the physical spelling.
- `T_CURRENT_ALARM.SEVERITY` has integer wires 1 through 4. Its canonical
  business values remain critical, major, minor and warning. SQL parameters
  must be integers in filters, projections and filtered measures.
- Network-device classification adds the source-declared TianGuan, printer,
  UPS, load-balancer and other-network-device values. Printer, UPS and
  load-balancer source wires have the `ne.category.` prefix. No aliases are
  inferred from generated rows.
- Manufacturer is an open source string with no exhaustive enum declaration.
  The Huawei-only canonical guard was removed from devices, fans and PSUs.
  Raw manufacturer filtering and grouping remain available without excluding
  undeclared manufacturers. A raw identifier such as `2011` is not silently
  rewritten into Huawei.

## Source discrepancies requiring explicit treatment

- The original `EnterpriseFrame` field list has no `id`. Current business
  `network/mappings/frame_sql.telora` explicitly adds it from query examples.
  The refreshed source model must distinguish this supplemental field from
  original schema facts and must not claim the original snapshot proves it.
- `OCCURUTC`, `ARRIVEUTC` and `OCCURTIME` are raw `long` values. The UTC/local
  distinction is documented, but the epoch unit is not uniformly specified.
  Current business mappings adapt UTC fields to timestamps and explicitly
  record the unresolved unit conversion. The old text-clock declarations
  are still pending correction; their test success cannot establish raw
  storage correctness.
- Several challenge relations add tenant equalities absent from the original
  conditions. These stricter pressure assumptions require review and cannot
  be presented as the original relationships.
- Original device/site OR relations declare M:1, while the challenge model
  declares multiple targets. Declared cardinality must be reconciled with
  source evidence independently of key shape. Source cardinality alone does
  not specify whether participation is mandatory.
