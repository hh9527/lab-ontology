# Source metadata refresh

Tracked in lab-ontology issue #32, branch `refresh/32-icloud-source-metadata`.
The prepared source model covers all 48 tables and 822 fields, with 50
carriers including two scoped PON roles, 95 valid original relationships
and 28 reconciled business relationship aliases.

## Authority and provenance

The files under `imaster-cloud/.compact/metadata/` are the single source of
truth (SSOT), confirmed by the project owner on 2026-10-01. This includes
the `*.logical.yaml` and `*.relation.yaml` inputs used by the source catalog.
Current business definitions under `imaster-cloud/telora/src/modeling/icloud`
provide secondary interpretations; when they conflict with the metadata,
the metadata takes precedence. Generated data and query examples do not
establish physical or business facts. Missing or malformed metadata does not
make secondary material authoritative: any supplementation or modeling
assumption must remain explicitly recorded as an exception, rather than
silently changing the source contract.

`../data/source_catalog.json` records all 48 logical datasets, all 97 source
relations, field types, nullability, primary-key markers, descriptions and
semantic properties. Each input file has a SHA-256 digest. The catalog is
review evidence, not a runtime data source or a substitute for model declarations.
It is generated by `scripts/icloud-source-catalog.py` using a YAML parser.

## Confirmed corrections

`icloud-source-v19` publishes storage resource name search with Appellation and
the existing ID reference. Storage/FC memory, disk utilization and disk read/write
I/O size each declare primary arithmetic Avg and sample-summary Max/Min. Source
YAML specifies percent for CPU/memory/utilization and kilobyte for I/O size;
the catalog preserves `unitName` and `unitType`. TODO(#58): confirm the kilobyte
byte multiplier before conversion. Disk identity and owner relation are still
source discrepancies; no replacement relationship or disk key is inferred.

`icloud-source-v9` declares FC entity grain and both owner paths for the shared
storage/FC CPU measure. Knowledge directory vocabulary entries publish
canonical IDs and owners. GraphPair rejects disjoint time windows on aligned
time identities; owner-level period comparisons remain available.

`icloud-source-v8` adds stored-sample CPU Avg/Min/Max for storage/FC and PON.
The unit is assumed to be `%`; TODO(#47): confirm against source metadata.
See [SAMPLE_STATISTICS.md](SAMPLE_STATISTICS.md) for population and weighting
semantics. Collaboration devices have no declared CPU source.

`icloud-source-v7` introduces explicit GraphPair identity alignment, per-column
output sides and comparison operands. Source declarations remain unchanged.
The preceding `icloud-source-v6` replaces space-separated KPI clocks with
DatetimeUtc ISO-Z encoding and publishes DateUtc logical dates. The v4
sample-statistics definitions remain unchanged.
See [SAMPLE_STATISTICS.md](SAMPLE_STATISTICS.md) for declared sample/Avg/Max/Min
IDs, NULL and threshold meanings, and the unresolved device port-usage formula.

- `EnterprisePhysicalLink.linkStatus` is the physical status column.
  `link_status` remains the model field name, not the physical spelling.
- `T_CURRENT_ALARM.SEVERITY` has integer wires 1 through 4. Its canonical
  business values remain critical, major, minor and warning. SQL parameters
  must be integers in filters, projections and filtered measures.
- Network-device classification adds the source-declared TianGuan, printer,
  UPS, load-balancer and other-network-device values. Printer, UPS and
  load-balancer source wires have the `ne.category.` prefix. No aliases are
  inferred from generated rows during the source refresh. Issue #29 subsequently
  adopts an explicit half-open assumption and declares the bare `printer`,
  `ups` and `lb` spellings as additional wires; see the assumption below.
- Manufacturer is an open source string with no exhaustive enum declaration.
  The Huawei-only canonical guard was removed from devices, fans and PSUs.
  Raw manufacturer filtering and grouping remain available without excluding
  undeclared manufacturers. A raw identifier such as `2011` is not silently
  rewritten into Huawei.

## Source discrepancies requiring explicit treatment

- Under the issue #29 working assumption, `device_class` is a half-open domain.
  Known concepts preserve all source wires; printer, UPS and load balancer also
  explicitly accept their bare spellings. This is an authorized modeling
  assumption, not a new fact proved by the source metadata or generated rows.
  Unrecognized classes retain their raw string and Unknown tag instead of
  disappearing from projection/grouping. `others` remains the known business
  concept encoded by `ne.category.unknown`, separate from the Unknown branch.
  See [the shared contract](../../ontology/docs/HALF-OPEN.md).

- `EnterpriseFrame` has no physical `id`; the supplemental field and its
  invented identity grain have been removed. Its `frameDn` is a Distinguished
  Name and declares the unique `dn` reference, as confirmed by the project
  owner. Source nullability is expressed with `Option(T)` for all nullable
  frame fields. A missing DN makes that reference unavailable; it does not
  identify a shared NULL object. Frame queries and relations remain available,
  but object counts and identity grouping have no declared total identity.
- `OCCURUTC`, `ARRIVEUTC` and `OCCURTIME` are raw `long` values. The UTC/local
  distinction is documented, but the epoch unit is not uniformly specified.
  Current business mappings adapt UTC fields to timestamps and explicitly
  record the unresolved unit conversion. These fields now use Int and
  provisionally use standard `EpochMillis`, with TODOs beside declarations.
  ACKUTC specifies milliseconds and ARRIVEUTC specifies millisecond precision,
  supporting this assumption. Time windows bind integer milliseconds.
  EpochMillis is independent of timezone; any special wall-clock integer
  representation would require its own specified encoding.
- Several challenge relations add tenant equalities absent from the original
  conditions. These equalities are removed from the source model and retained
  only in the independent synthetic pressure fixture.
- Original device/site OR relations declare M:1, while the challenge model
  declares multiple targets. The source model trusts declared M:1 independently
  of key shape. Original 1 maps to Optional and M/N to Many0, since minimum
  participation is unspecified. Unusual original 1:M tenant relations are
  preserved as declared.

## Additional corrections and exceptions

- Device and server grain use the original primary key `id`.
- Original primary-key markers are preserved even on curated KPI carriers;
  their separately declared business grain still identifies sampled rows.
  Tenant.TENANT_ID and Site.SITE_ID are supplemental business identities,
  explicitly recorded because their original isPK markers are N.
- All original integer timestamp fields use standard EpochMillis. Where the
  source does not establish a unit, the source declaration carries a TODO.
  Under the #44 contract, datetime KPI clocks use DatetimeUtc with confirmed
  UTC semantics and SQLite `YYYY-MM-DDTHH:MM:SSZ` encoding. This supersedes
  the #41 space-separated Utc1 assumption. Source-declared `YYYY-MM-DD` manufacturing dates
  use DateUtc instead. These provisional decisions are tracked in author-facing
  audit material, not as questions for the querying Agent. Knowledge publishes
  the current Model contract. See [TIME_COVERAGE.md](TIME_COVERAGE.md).
- The fixed subject/authorize layer is removed. Query and discovery factories
  bind only the prepared model and relevant backend/domain. Dimension
  visibility remains a model capability; authentication belongs to the host.
- Source-only carriers expose raw fields without invented sample grains.
  Online-rate Avg/Min/Max measures additionally expose the arithmetic mean or
  extrema of stored values, not time-weighted or effective-count-weighted rates. They do not
  establish sample uniqueness or infer a numeric scale. Time formats follow the
  explicit convention above.
  UUID/IP use String, float/double
  use Float, integer/long use Int. Nullability remains recorded in the catalog;
  runtime scalar types describe the non-null value, not a NOT NULL assertion.
- Every source enum wire is represented. EnterpriseSlot.operstatus has malformed
  embedded JSON; its 12 values are recovered explicitly from current
  `network/entity_sets/slot_values.telora`.
- EnterpriseOpticalModule_X_TENANT_VIEW references absent tenantId;
  SYS_StorageDisk_StorageHardDriveKPI references absent SYS_StorageDisk.id.
  These two original relations are excluded with recorded reasons.
- Derived alarm/site guard and physical-link A/Z participation remain explicit
  business relationships. PON ONU/OLT carriers preserve scoped business roles.

## Field capabilities

Issue #34 reconciles the whole source model using the reviewed policy in
[FIELD_CAPABILITIES.md](FIELD_CAPABILITIES.md). Names, aliases, versions, SNs,
open descriptions/product labels and address representations now have consistent
text search capabilities; canonical values, identities and clocks keep their
semantic boundaries. The source policy is shared by generation, reconciliation
and compiled-model audit rather than tied to individual query examples.

Raw address storage remains String. Seventeen explicit computed IPv4 views
retain only canonical IPv4 values and yield NULL for other representations;
they do not assert an unproved source encoding. The original dimensions remain
available for literal text search. This adds no physical fields or relationships.

The complete prepared model publishes 245 searchable text dimensions and 17
IPv4 views. The source audit reports per-family coverage and checks every
published capability, not only representative queries.

## Verification Commands

```sh
bin/telora -C icloud_model eval @src/source_audit:report --with-memory-limit 1024 > /tmp/icloud-prepared.json
mise x -- python3 scripts/audit-icloud-model.py /tmp/icloud-prepared.json --metadata ../imaster-cloud/.compact/metadata
bin/telora -C icloud_model test graph --request-fuel 10000 --with-memory-limit 1024
bin/telora -C icloud_model test knowledge --initialization-fuel 100000 --request-fuel 500000 --with-memory-limit 1024
bin/telora -C icloud_model test pressure_graph --request-fuel 10000 --with-memory-limit 1024
```

The audit compares compiled physical fields/types, enum wires, relation keys
and cardinalities to source evidence, and checks all source file hashes.
`graph` and `knowledge` exercise the product model. Historical 198 pressure
cases use `tests/pressure_graph/model_fixture.telora`; passing them does not
prove source correctness. DOMAIN.md and PRESSURE_FAMILIES.md describe that
synthetic fixture.

Build and verify the current publication:

```sh
bin/telora -C icloud_model build icloud_model --snapshot -o bin/icloud_model.snapshot.wasm --initialization-fuel 100000 --request-fuel 100000 --with-memory-limit 1024
mise x -- python3 scripts/check-icloud-publication.py /tmp/icloud-prepared.json bin/icloud_model.snapshot.wasm
```

The publication probe reads all 50 dataset documents, 126 relation documents
and every authorized dimension document, checks index uniqueness and reference
closure, verifies advertised operators/types and IPv4-view contracts, and lowers
version suffix search, literal address search, IPv4 subnet search and a
millisecond window with integer severity wires.
`../data/source_audit_summary.json` records the final compiled coverage check.
