# JS 生成模型的知识构建时间分布

测量日期：2026-10-26。模型源码基于 `a589466`，Telora 基于 `54aa4e21`。本次只做隔离诊断，没有修改或重启部署环境。

## 方法

使用现有 JS 生成器构造 5／10／20／40 个 Dataset，各有 10 个维度、11 个 Row 字段、复合身份与一个记录计数，无关系。主样本的 9 个值字段分别使用独立 newtype；对照样本改用 String，身份和 Row 类型仍然独立。

在隔离副本将同一知识导出函数逐段截断：声明与 transform、类型种子、类型闭包、类型事实、Dataset 事实、授权事实、合并、完整编码。所有变体使用同一构建期 stage 边界及 transform 程序。截断点通过长度输出强制消费中间结果；最后一档输出实际 v4 知识。取相邻制品 `service_prepare` 耗时差，估计阶段成本。

每档顺序构建一次，不并发；独立 newtype 样本正序，String 对照反序。所有 40 次构建的 transform 冒烟响应在同一样本的各变体间完全一致。没有执行模型自检、知识发现接口或插件反向链接派生。

这是实际构建路径的差分实验，不是单次构建内的嵌套秒表。各变体的代码、活跃对象、GC 与 P2 大小不同；尤其最后一档包含语言 Value 编码及宿主接收信息的增量。微小差异不能视为稳定性能结论，单轮结果不承诺吞吐或精确占比。

## 观察与下一步

类型收集的阶段增量随 Dataset 数量为 0.076／0.266／0.862／3.232 秒，接近平方增长。`collect_types` 当前逐项对 seen／fresh 数组做线性查重；这是源码中可以直接对应的算法热点。String 对照将该增量降到 0.186 秒，支持优先检查不同 TypeId 数量与去重算法的影响。

40 Dataset 独立 newtype 样本中，Dataset 事实构造与合并合计约 7.30 秒，占知识额外准备成本（17.168−1.282 秒）的约 46%。String 对照这两项仍需约 5.63 秒。这支持探索由模型提供根声明、共享类型描述及显式映射，插件展开成员与完整图；不意味着这些成本能全部消失或无代价转移。

类型事实还有约 2.94 秒，涉及反射、类型身份／引用构造与编码；当前测量尚未将它们进一步拆开。不能将整段都归因于反射或 GC，也不能把所有图构造成本直接当作未来可节省时间。

建议先实验类型闭包去重，再以同一套样本比较紧凑描述与完整 v4 输出，并计算插件展开成本。IC 的约 37 秒准备包含不同声明分布，本报告没有测 IC，不能直接套用本样本占比。

## 复验

```sh
python3 scripts/measure-generated-knowledge.py --counts 5,10,20,40 --dimensions 10 --field-types distinct
python3 scripts/measure-generated-knowledge.py --counts 40 --dimensions 10 --field-types plain --reverse
```

脚本将每轮原始阶段日志、请求响应与 `report.json` 保存到 TMPDIR 或 `~/.cache/tmp/knowledge-distribution-*`。诊断 Wasm 会删除，不能拿截断变体部署。
