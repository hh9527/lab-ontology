# 缓存字段类型投影实验

## 表达

```text
generate_field_type_info(memorizer, ty) -> (tys, info)
```

`tys` 是展开内嵌结构后遇到的具名类型，遇到具名边界即停止；World 自检检查这些类型是否显式登记，不自动补充成员。引用在组合时可以重复，自检不属于构建准备的默认路径。

`info` 包含可读的内联类型表达和具名引用地址。比如 `Option(DateTimeUtc)` 产生 `[DateTimeUtc.type]`，字段表达为 `Option(types/...)`。`Array(Option(String))` 不产生具名依赖。匿名 Struct、Enum、Tuple 等由所属定义内联表达；具名递归类型直接返回引用，不展开其定义。

模块提供固定投影函数的共享 TypeMemorizer，缓存整个 `(tys, info)`；递归投影也查询该缓存。缓存槽位、命中状态和条目数量没有观察接口。

实现见 `ontology/src/field_type_info.telora`。`field_knowledge.telora` 将该投影接入显式 World 的知识发布；类型发布数组直接来自 World 的具名类型清单，不建立匿名类型闭包。字段、角色、Group、表达式等使用相同的缓存投影。

静态 JS 消费类型信息中的 text 和 references。业务图仍使用原有字段类型文本和具名引用地址；具名类型的匿名 representation 直接内联为描述文本。内置类型和容器没有独立节点，匿名结构也不生成独立节点。

## NS 对照

```sh
python3 scripts/check-field-type-info.py
```

脚本在临时工作区依次使用当前 HEAD 的 World 和工作区实验实现构建 NS；编译器、模型、配额保持一致，不部署制品。2026-10-27 各一次顺序观测：

| 指标 | HEAD World | 缓存字段投影 |
| --- | --- | --- |
| 构建期准备 | 51.595 秒 | 35.012 秒 |
| 总构建 | 72.199 秒 | 55.752 秒 |
| 构建期 fuel | 122.662 十亿 | 82.655 十亿 |
| 类型描述条目 | 6,704 | 596 |
| 知识发布 JSON | 7,372,839 字节 | 5,605,351 字节 |
| Wasm 制品 | 23,683,180 字节 | 21,917,969 字节 |
| 构建期线性内存容量 | 122,486,784 字节 | 102,170,624 字节 |
| 构建期累计分配 | 201,356,979 字节 | 137,321,210 字节 |
| GC 次数 | 63 | 53 |
| 准备结束时托管存活字节 | 41,548,882 | 42,464,049 |

准备耗时减少约 32.1%，总构建减少约 22.8%。缓存使准备结束时托管存活字节增加约 0.87 MiB，但累计分配和线性内存容量减少。结束时存活字节包含未强制回收的临时对象，不代表缓存自身大小；线性内存容量也不是进程 RSS。

这是组合修改的收益：取消重复结构描述、改为内联表达、缓存字段投影同时生效，不能将全部收益单独归因于 TypeMemorizer。

## 验证

- 8 项字段投影测试通过，覆盖内置嵌套容器、时间类型、具名容器、匿名字段、递归类型、重复调用与 World 覆盖诊断
- NS 对照中所有非类型根节点和类型成员节点完全一致，包括字段、值域、Group、关系与引用
- 具名类型的名称、kind、反向引用策略、arguments、field_types、variants 一致
- 减少的 236 个节点全部是匿名类型根；新图无悬空引用
- NS transform 通过 151 个 Dataset 投影、302 条关系 SQL、48 类采样、规范值域及非法输入检查
- 内置类型知识回归通过，具名容器身份和内嵌模型引用保持正确

正常 transform 与 SQL 验证不等价于完整模型自检；本实验没有执行 NS 完整自检。

原始报告位于本机 `~/.cache/tmp/field-type-info-fbc57qb9/report.json`，包含两次构建日志、制品、发布 JSON 和静态 JS 组图结果。

## 剩余空间

发布 JSON 仍有约 5.6 MB：Dataset 描述和 capabilities 各自承担不同信息，字段类型信息也会随引用点内联输出。缓存主要消除重复计算，不会自动消除所有重复字节。若继续优化，应分别测量这两部分，不能将剩余 35 秒都归因于 JSON 编码。

实验将字段投影发布独立放在 `field_knowledge.telora`，便于与已有发布路径对照；合入准备时需要收敛两条路径共享的描述生成逻辑。

## IC 对照

```sh
python3 scripts/check-field-type-info.py --model icloud_model
```

IC 以模块内 `world_types` 和 `world_entities` 清单登记 275 个具名类型、29 个 Entity；World 共享既有的 50 个 Dataset 声明，并显式给出 Relation、Alternative、Link 和 profile。内嵌字段不登记为独立根。既有 transform 的 `prepared` 构造表达式保持一致，构建期发布直接使用这份 Prepared。

对照分为当前自动发现、显式 World、显式 World 加缓存字段投影三组。每组构建两次，顺序为自动发现／World／缓存，再反向执行；两轮发布内容分别一致。以下为两次耗时的均值，样本规模不足以证明约 1% 的稳定加速：

| 指标 | 当前自动发现 | 显式 World | World＋缓存投影 |
| --- | --- | --- | --- |
| 准备耗时 | 11.702 秒 | 11.117 秒 | 11.373 秒 |
| 总构建 | 24.416 秒 | 23.831 秒 | 24.191 秒 |
| 构建期 fuel | 26.767 十亿 | 25.249 十亿 | 26.129 十亿 |
| 类型描述条目 | 366 | 581 | 275 |
| 知识发布 JSON | 1,551,004 字节 | 1,603,932 字节 | 1,899,061 字节 |
| Wasm 制品 | 13,418,152 字节 | 13,476,233 字节 | 13,773,630 字节 |
| 构建期线性内存容量 | 28.25 MiB | 34.81 MiB | 34.81 MiB |
| 构建期累计分配 | 48,083,469 字节 | 47,404,951 字节 | 48,359,218 字节 |
| GC 次数 | 49 | 46 | 45 |

IC 当前路径的闭包收集已经去重，366 条类型描述没有 NS 中 6,704 条描述的重复规模。显式 World 的局部结构投影产生 581 条描述，缓存内联版只输出 275 个根，但每个类型引用位置都携带 text 和 references，增加了重复字节和 Value 编码工作。

按指令拆分的 JSON 字节数：

| 描述部分 | 当前自动发现 | 显式 World | World＋缓存投影 |
| --- | --- | --- | --- |
| types | 327,577 | 388,830 | 386,795 |
| entity | 9,769 | 2,524 | 5,318 |
| dataset | 751,164 | 751,164 | 1,045,534 |
| capabilities | 429,654 | 429,654 | 429,654 |
| relations | 17,460 | 17,460 | 17,460 |

因此当前组合实现对 IC 没有明显性能收益：相对自动发现，总耗时约减少 0.9%，制品增加约 347 KiB，构建期线性内存容量增加约 6.56 MiB；缓存版还比单独使用 World 慢约 1.5%。这不是缓存本身无效的结论，而是缓存计算收益与当前信息编码开销的合并结果。下一步应比较共享引用信息或更紧凑的字段类型表示，避免把完整 references 数组随每个引用点重复输出。

验证结果：

- 自动发现与显式 World 的 4,557 条知识事实完全一致，登记的 275 个具名类型与原模型一致
- 缓存版保留全部非类型内容和具名类型字段，没有悬空引用；减少的 82 个节点全部是匿名类型根
- 基线及缓存版均通过 50 个 Dataset SQL 投影、带数据的 limit／规范值域／IPv4／过滤计数／计算计数／Latest／GraphPair／GraphUnion、重复请求及混合批次拒绝检查
- 没有运行 IC 完整自检，也没有部署

原始记录：本机 `~/.cache/tmp/field-type-info-0d3429df/{report.json,repeat-report.json}`。反向复测脚本同目录 `repeat.py`，逐组核对发布 JSON 与首次构建一致。

探索中曾将 transform 构造改为直接从新 World 读取全部参数，中间版本在构建期触发 Wasm 内存越界。最终实现保留既有 Prepared 构造，World 共享其 Dataset 声明，已通过上述两轮构建和 SQL 验证；该中间表达式的越界原因尚未定位。失败版本与日志上下文位于本机 `~/.cache/tmp/field-type-info-i7zvrze5`，不能把本实验视为该编译器问题已修复。
