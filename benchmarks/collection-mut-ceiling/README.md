# IC/NS：先验证手写集合缓冲的收益

这是最初单路径实验的历史记录；最新整段构图对照见 [whole-graph.md](whole-graph.md)。
默认 ontology 源码已恢复不可变实现；手写片段仅放在本目录的实验夹具中。
实验编译器必须显式启用 `--features experimental-mut-oracle`，默认不包含任何 oracle 入口。

先在真实应用中证明手写版本有收益，再考虑自动 alias 分析。此前的
JSON 编码融合实验不能证明 XxxMut 的收益，也不能作为编译器设计依据。

## 实验边界

- 同一输入、输出、遍历顺序、去重和错误行为。
- 先允许实验版手写内部缓冲，不把该写法或临时 API 作为语言设计提案。
- 区分三层：现有实现；同算法的手写缓冲实现；改变遍历/缓存算法的实现。
- 用完整 staged 构建验证知识发布数据，观察准备时间、fuel、累计分配与 GC。
- 手写版本有明确收益以后，才研究如何从普通 Xxx 写法自动生成对应 XxxMut。
- 单次墙钟数据只能用于初筛；不能把波动宣称为性能提升。

## 原理检查

| 真实路径 | 当前实现 | 手写缓冲可能消除的工作 | 限制 |
| --- | --- | --- | --- |
| field_knowledge::declaration_types | 多层 flat_map/concat 生成并复制子数组 | 整个遍历共用 ArrayMut，取消中间拼接缓冲 | 最终数组仍需存在；回调调用开销不可忽略 |
| field_knowledge::discover_indexed | 每轮 collect_dict 重建已经发现的类型索引 | 同一个 MapMut 跨轮存活，只加入新类型 | 每轮 fresh 的边界、顺序必须保持；需先量每轮规模 |
| field_type_info::compute | 多数文本用 map + join 生成 | 可能省一些临时片段数组 | join 已是批量构造，不存在普遍的逐字符二次复制证据 |
| codec Array/Record 编码 | 后端预先按已知长度分配输出缓冲 | 不能假设换 Mut 就消除一轮全表复制 | 输出分配和递归编码仍是必要工作 |
| Array push | 已有安全的尾部追加优化 | 分叉/无法追加时或有空间 | 不能按每次 push 都复制整个数组估算 |

## 首个手写 ArrayMut 实验

只替换 declaration_types；按原顺序逐个输出 Type，保留重复项。
实验专用 alias_probe_collect 在 std::pipeline 内创建私有 ArrayMut，并在
嵌套遍历完成后 finish。它只是测量支架，既不是公开 API 提案，也不是
最优机器码的理论上限；额外的回调调用还可能抵消节省。

IC 同一实验编译器的单次结果：

| 指标 | 原实现 | 手写 ArrayMut |
| --- | ---: | ---: |
| 构建期准备 | 11.348 s | 11.484 s |
| 累计分配 | 50,880,990 B | 50,564,378 B |
| fuel | 25,402,257,347 | 25,444,571,464 |
| GC 次数 | 45 | 45 |

完整 build information（包括全部知识数据与数组顺序）严格相同。
只省 316,612 B（约 0.62%），fuel 略增，没有加速证据。
因此暂不为这个路径扩大自动分析。也不能由此推断所有 ArrayMut 路径无益。

后续先审查跨轮类型索引的实际重建规模，建立 MapMut 的手写对照；
不先设计跨函数分析，也不把算法改变的收益归入 alias 优化。

NS 同一编译器的单次结果：准备 36.299 → 35.586 s；
fuel 85,298,203,120 → 82,818,260,687；
累计分配 143,275,521 → 142,254,849 B。
单次耗时不用于证明稳定加速，fuel 和分配用于确认这一局部工作量的变化。
两模型完整知识数据均严格一致；IC 17 组时间查询检查通过；NS 151 个 Dataset、
302 个 Relation、48 组度量、规范值和非法输入检查通过。

历史单路径数据对应早期实验提交，不能用来复现当前更完整的手写版本。
现行复现方式、默认关闭的实验开关和全流程结果见 [whole-graph.md](whole-graph.md)。
